# 飞书 / 钉钉身份绑定

一个 dsh-ee 账号可以同时带一个飞书身份和一个钉钉身份。同一名员工用哪边登录，进的都是同一个账号、同一份令牌、额度和权限。

## 管理员：开第二登录入口

「系统设置 → 登录方式」里，主登录方式选飞书（或钉钉）并开启后，在下面的「第二登录入口」里配另一个。要求：

- 主登录方式已开启，并且两边**一个是飞书、一个是钉钉**。主登录方式关掉或换成别的 IdP，第二入口自动失效，不需要清配置。
- 两个应用登记同一个回调地址 `https://<dsh-ee>/api/auth/oidc/callback`。
- 第二入口只管**登录、组织同步和身份关联**。飞书通知、卡片审批、飞书 / 钉钉机器人对话仍然只跟主登录方式走，并且只认账号的主身份。

登录页会出现两个按钮；`/api/auth/oidc/start?provider=feishu|dingtalk` 指定入口，不带参数是主登录方式。

## 数据模型

- `users.external_dn` 仍是账号的**主身份**：账号建出来时的那个（`feishu:<open_id>` 或 `dingtalk:<CorpId>:<userId>`）。显示名、部门、邮箱和「组与角色的映射」只由主身份所在的来源在登录和同步时更新，另一边不动它们，两边的映射不会互相打架。
- `user_identities`（迁移 `0047_user_identities.sql`）记每个账号的飞书 / 钉钉身份：`via=home` 是主身份的镜像，`explicit` / `mobile` / `email` 是**关联身份**及其来历。约束：一个身份只能属于一个账号（`subject` 唯一），一个账号在每个来源上最多一个身份（`user_id + provider` 唯一）。
- 表里还存目录里核实过的手机号和企业邮箱的 **SHA-256 摘要**（不存明文），只用来比对。

## 绑定规则

登录或组织同步遇到一个飞书 / 钉钉身份时，按顺序：

1. **已知身份**：是某个账号的主身份或关联身份，就是那个账号。账号被禁用则拒绝登录。
2. **员工自己绑定（显式）**：员工先用任一入口登录，在「个人账号 → 飞书 / 钉钉身份」点「绑定」，到另一边完成一次真实的授权登录。只有同时满足才绑定：
   - 发起绑定的会话还在，且是完整会话（从 DSH 打开的受限会话不行）；
   - 账号是通过企业统一登录建立的员工账号（本地账号、LDAP 账号、机器人不能绑）；
   - 这个身份不属于任何别的账号——已经是别人的主身份或关联身份就拒绝，**不改挂、不合并账号**；
   - 当前账号在这个来源上还没有身份（要换先解除）。
3. **按核实过的联系方式自动关联**（默认**关**，第二入口上的开关 `linkByContact`）：开启后，一个还没见过的身份会和「另一个来源建的账号」比对，全部满足才关联：
   - 比对的值只取 dsh-ee 服务端用应用凭据从企业通讯录读到的：**手机号**（两边都是账号的登录号码，带国际区号归一后比较；缺区号不比）和**企业分配的邮箱**（钉钉 `org_email`、飞书 `enterprise_email`）；
   - **不参与比对**：员工自己填的邮箱（钉钉 `email`、飞书 `email`）、显示名、用户名、工号，以及登录时 IdP 声明里的任何字段；
   - 恰好命中**一个**账号；手机号和企业邮箱分别指向不同账号、或者一项对上而另一项两边都有却不一样，都算有歧义，不关联；
   - 命中的账号是在用的企业统一登录员工账号，并且在这个来源上还没有身份（同手机号的第二个人不会顶掉已有的绑定）。
4. **都不满足**：按原来的规则处理——开了自动建号就建一个独立的新账号，没开就拒绝登录 / 同步里记为跳过；用户名撞上已绑定别的身份的账号时报冲突。任何情况下都不会仅凭用户名、显示名或没核实过的邮箱把人并进已有账号。

要让自动关联有东西可比，两边都要读到联系方式：各跑一次组织同步（或让员工各登录一次），并给两个应用开通手机号 / 企业邮箱的读权限。读不到就只是不自动关联，不影响登录。

## 解除与离职

- 员工可以在「个人账号」解除自己的**关联身份**；主身份只能由管理员在用户管理里「解除身份绑定」，那会连同关联身份一起清掉并踢下会话。
- 组织同步发现人离职（需要开对应的同步禁用开关，且来源明确确认）：
  - 离职的是账号的**主身份**所在来源：禁用账号，两条登录路径都进不来；
  - 离职的只是**关联身份**所在来源：只解除这条关联，账号不禁用（它归主身份那边管），结果里单独列出。
- 所有绑定、自动关联、解除都写审计：`oidc.identity_link`（`via=explicit|mobile|email`）、`oidc.identity_unlink`。

## 接口

- `GET /api/me/identities`：当前账号的两个身份及能否绑定 / 解除（第二入口没开时为空）。
- `GET /api/auth/oidc/start?provider=<feishu|dingtalk>&bind=1`：发起绑定，结果回到 `/account?identity_bound=…` 或 `/account?identity_error=…`。
- `DELETE /api/me/identities/{provider}`：解除自己的关联身份。
- `GET/PUT /api/admin/auth/oidc?slot=secondary`、`POST /api/admin/auth/oidc/test?slot=secondary`：第二入口的配置，权限与主登录方式相同。

## 验证

```sh
cd server
DSH_EE_TEST_DSN='root:@tcp(127.0.0.1:4000)/' go test -count=1 ./internal/api -run 'TestFeishuDingTalkIdentityBinding|TestDingTalkOrganizationSync'
```

`TestFeishuDingTalkIdentityBinding` 用假飞书（OIDC + 通讯录）和假钉钉（OAuth + 通讯录）覆盖：没绑定时手机号对得上也不合并、显式绑定后两条登录路径是同一个账号、别人的身份和本地账号不能绑、自动关联只认核实过的手机号而不认自填邮箱、关联身份离职只解除关联、主身份离职禁用账号、员工自己解除。
