## 是什么

[云端常驻机器人](/docs/cloud-runtime)的网页对话默认只属于所有者本人。共享之后，一个部门的同事可以在「机器人对话」页面（`/bot-chat`）一起用同一个机器人：

- 列表里多出一个带「团队」标记的入口，点进去是这个部门**共用的一条团队对话**，每条消息上标着是谁发的；
- 机器人生成的文件进团队文件库，部门里的人都能看到和下载，部门外的人看不到；
- 所有者自己和机器人的那条对话不受影响，也不会被共享。

团队就是员工资料里的**部门**（`users.department`，通常由 LDAP / 飞书目录同步），不需要另建团队或成员名单。员工调岗后，能看到的团队对话跟着变。

## 为什么是一条团队对话

共享机器人的对话是整个部门共用一条，而不是每人一条：

- 团队共享的目的就是像在群里一样协作：同事能接着别人的问题追问，机器人也能看到前面谁问了什么（提示词里每一轮都带发送人），产物自然是大家共同的；
- 每人一条的话，「共享」只是把机器人设定复制给每个人，同事之间看不到彼此的上下文，文件也散在各自的对话里，等于没有团队；
- 团队对话一次只处理一条消息（和个人对话一样），两个人同时发，后发的人会收到「上一条还在处理中」，等回复后再发。

代价是：在团队对话里问的问题和得到的回复，部门里所有人都能看到。页面顶部会一直提示这一点。不想让同事看到的内容，请在自己的个人对话里问。

## 用谁的身份和权限运行

**团队对话里的每一条消息，都以发这条消息的员工本人的身份运行**：

| 项目 | 团队对话里的一轮 |
| --- | --- |
| 运行身份（`run_as`） | 发消息的员工，不是机器人所有者 |
| 短期凭证 | 为发消息的员工签发的只读、短期令牌（任务超时即过期，结束后吊销） |
| 模型额度 / 排队上限 | 记在发消息的员工身上（每人最多 5 个排队或运行中的云任务） |
| 机器人设定（提示词） | 所有者 / 管理员配置的那份 |

所以共享不会把所有者的权限放大给整个团队：成员通过机器人能查到的数据，和他自己直接查一样多。没有模型使用权限的同部门员工能看到团队对话，但不能在里面发消息。

所有者的**定时任务**和管理员的「立即运行」仍然以所有者身份运行，它们的结果和文件**不会**出现在团队对话或团队文件库里。

## 怎么共享

默认不共享。机器人需要先由管理员开放网页对话。

- **所有者**：在 `/bot-chat` 打开自己机器人的资料栏，「动态」里有「共享给团队」，只能共享给自己资料上的部门；账号没填部门时不能共享。
- **管理员**：「云端常驻机器人」设置里编辑机器人，在「共享给部门」填部门名（与员工资料里的部门名一致），留空表示不共享。

同一时刻一个机器人只共享给一个部门。

机器人替员工新建的机器人（[`bots__create`](./bot-delegation.md#新建机器人) 建的临时助手）**不能由所有者共享给部门**：它的提示词由机器人 / 模型控制，共享给部门就等于让同事用本人的权限执行别人写的提示词。确实需要共享的，由管理员在「云端常驻机器人」设置里另行处理。

## 取消共享和改部门

- 取消共享（所有者或管理员都可以）**立即生效**：部门成员马上看不到团队入口、团队对话和团队文件，再访问一律 403；团队对话里还在排队或运行的消息会一并取消。
- 改共享给别的部门：新部门得到一条新的团队对话，**看不到**原部门的历史；以后再共享回原部门，原来的团队对话和历史会回来。
- 员工调到别的部门：立即看不到原部门的团队对话。

可见性在每次请求时按数据库里的当前值判断，没有缓存。

## 审计

| 动作 | 记录 |
| --- | --- |
| `runtime.bot.share` | 共享变更：操作人、机器人、`department`（新部门，空是取消）、`previous`、`by`（`owner` / `admin`） |
| `runtime.chat.team_turn` | 团队对话里谁触发了任务：操作人就是发消息的员工，带 `bot_id`、`conversation_id`、`department`、`run_as` |
| `runtime.task.<状态>` | 任务结束（已有），带 `run_as` |

## 接口

都是网页会话接口，不开放给 Agent 调用。

| 接口 | 说明 |
| --- | --- |
| `GET /api/runtime/chat/bots` | 团队入口带 `shared: true`、`department`、`owner_name`；所有者自己的入口带 `shared_department` |
| `POST /api/runtime/chat/conversations` | `{"bot_id": 1, "shared": true}` 取或建团队对话（幂等） |
| `GET /api/runtime/chat/conversations/{id}` | 团队对话的消息带 `sender_id`、`sender_name` |
| `POST /api/runtime/chat/conversations/{id}/messages` | 在团队对话里发消息，以当前员工身份运行 |
| `GET /api/runtime/chat/bots/{id}/profile?shared=1` | 团队资料：团队对话的运行状态和文件，不含所有者的定时设置 |
| `PUT /api/runtime/chat/bots/{id}/share` | 所有者：`{"shared": true}` 共享给自己的部门，`false` 取消 |
| `PUT /api/admin/runtime/bots/{id}/share` | 管理员（`settings.manage`）：`{"department": "研发部"}`，空串取消 |
| `GET /api/runtime/tasks/{id}/artifacts[/{artifact}]` | 团队成员可以查看、下载团队对话里任何一轮的文件；事件和取消仍只限触发人本人 |

团队外访问团队对话、团队资料或团队文件返回 403，错误码 `runtime_chat.team_forbidden`；所有者没填部门时共享返回 409 `runtime_chat.no_department`。
